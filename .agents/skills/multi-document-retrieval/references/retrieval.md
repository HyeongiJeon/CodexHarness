# Retrieval contract
TXT/Markdown locators are real lines and character offsets; CSV uses logical row and physical line interval; JSON uses a pointer; DOCX uses paragraph/table/row/cell; XLSX uses sheet/row/cell; PDF uses page and extraction character interval, never invented line numbers.

`corpus search` supports `--status`, `--entity`, `--date-from`, `--date-to`; date filters apply document_date, not effective interval. Literal is case-sensitive substring, including Korean. Identifier mode uses word/dash boundaries to avoid suffix distractors; it is not semantic entity resolution. FTS5 uses SQLite syntax and is not Korean morphological search. Regex has a three-second process timeout. Matches do not cross extraction segments; no-match does not prove corpus-wide absence. Index rebuild is atomic, not incremental.

Metadata header keys: document_date, version, status, effective_from, effective_to, entity. A `--metadata manifest.json` can supply metadata, but unaudited overrides are not authenticated source facts. Incomplete sources remain visible and deterministic synthesis refuses a supported answer for a known-incomplete corpus. Packs bound serialized JSON character count (UTF-8 byte size may be larger), deduplicate exact slices and retain distinct citation IDs for distant matches in one segment. Default 2M text characters per document; cap truncation is explicit.
