# Final Delivery Verification

Original project and exam instructions take precedence over this workflow.
Exam profile: no Astra, computer-use, push, external uploads, or AI-prohibited written answers.

**Inputs:** Final artifacts/code, acceptance evidence, submission format, launch steps, limitations.

Before the last check, especially for exam submission, read [references/handoff-checks.md](references/handoff-checks.md).

## Procedure

1. Inspect final files and repository state; artifacts must exist, be nonempty, and match the tested state. Preserve unrelated user work.
2. Follow launch/open instructions using actual paths; check configuration names, dependencies, output locations, and required format.
3. Reconcile claims with evidence; identify failed/unverified requirements and simulated behavior without overstating review coverage.
4. Deliver exact artifact links/paths, concise usage, validation results, and material limits. Keep delivery local unless an external action is both permitted and authorized.

**Output contract:** Self-contained handoff with real deliverables, exact usage, evidence summary, and unresolved requirements.

**Tools:** git status/diff, local file inspection, launch commands, artifact viewers; no push, external upload, or computer-use.

**Verification:** A reviewer can find and use the output from the handoff alone; every success claim has current evidence.

**Failure handling:** Fix packaging/launch failures and recheck within the reserve; otherwise report the concrete blocker and deliver useful artifacts without claiming completion.
